3 Description de l'application et de son usage de la cryptologie

L'application Cooksy est une application mobile iOS qui convertit des vidéos culinaires (issues de plateformes telles que TikTok, Instagram, etc.) en recettes structurées, claires et directement utilisables par l'utilisateur.

Elle utilise exclusivement les protocoles de communication sécurisés standard fournis par le système d'exploitation Apple iOS, à savoir HTTPS/TLS via le framework natif URLSession (Foundation framework). Aucun algorithme de chiffrement propriétaire ou personnalisé n'est implémenté dans le code source de l'application. L'application ne stocke, ne gère, ni ne transmet de clés cryptographiques de manière autonome.

L'utilisation de la cryptologie se limite strictement à la sécurisation des échanges réseau entre l'application et les serveurs distants (API tierces, services Apple), conformément aux bonnes pratiques imposées par Apple (App Transport Security — ATS).

4 Algorithmes et protocoles cryptographiques mis en œuvre
Algorithme / Protocole Version / Paramètres Origine Usage
TLS (Transport Layer Security) TLS 1.2 / TLS 1.3 Fourni par Apple iOS (SecureTransport / Network.framework) Chiffrement des communications HTTPS
AES (Advanced Encryption Standard) AES-256 Intégré au système Apple iOS (CryptoKit) Chiffrement symétrique dans le cadre de TLS
RSA / ECDSA RSA-2048 / ECDSA P-256 Intégré au système Apple iOS Authentification des certificats TLS (handshake)
SHA (Secure Hash Algorithm) SHA-256 / SHA-384 Intégré au système Apple iOS Intégrité dans le protocole TLS

Note : Tous ces algorithmes sont standard, publics, non-propriétaires, et fournis exclusivement via les API système d'Apple. L'application n'intègre aucune bibliothèque cryptographique tierce (OpenSSL, Bouncy Castle, etc.).

5 Fonction assurée par la cryptologie
Fonction principale : Confidentialité des communications réseau
Périmètre : Transfert de données entre l'application et les serveurs distants via HTTPS standard
Authentification : Assurée via les certificats TLS — gérée intégralement par iOS
Stockage chiffré : Non applicable — pas de chiffrement de données locales personnalisé
Gestion de clés : Aucune — délégation totale au système iOS (Keychain / SecureEnclave)
